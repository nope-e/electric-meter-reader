日期：2026-10-19。已跑通最大面积窗口定位后的数字识别。使用现成权重，未训练、未微调，没有透视校正、锐化或生成修复。

首次缩略图转录后，放大原始未画框窗口复核，修正了 `7424`、`7628`、`7658`、`7742` 四张的人工标签，并将 `7595` 从可评分改为反光下无法确定。旧转录和复核说明均保留在 `lcd_reference.json`，模型输出不受标签影响。

## 参考更正和难例

- `1792403668125.jpg`：用户确认读数为 `6973.16`，与模型预测 `697316` 一致。此前助手误转录为 `697376`（6973.76），属于参考标注错误，已更正；旧转录和用户确认说明保留在 `lcd_reference.json`。
- `1792403667284.jpg`：窗口右侧被原图裁掉，模型输出 `102544`，会按固定小数规则得到 `1025.44`。本版将其标为 `review/window_touches_image_edge`，不能接受为完整读数。
- `1792403667493.jpg`：强反光下输出 `00636`，存在漏位和错位风险。即使模型给出非空数字串，也不能认为已可靠识别。
- `1792403667595.jpg`、`1792403667873.jpg`、`1792403668045.jpg`：分别输出 `951956`、`757053`、`717678`，因原图反光或低对比度未确认参考。它们不计分，并不表示识别正确。

本版每张保留原始预测，供检查；**没有自动图像质量模型或经过验证的自动提交阈值**。输出 `candidate` 只表示候选，不表示通过抄表验收。

## 推理方式和模型

1. 复用窗口检测结果，在阈值 0.25、NMS 0.45 后选择最大面积窗口。
2. 按坐标从原图重新裁剪，等比例缩放并补边到 640×640，RGB、NCHW、float32 / 255。
3. ONNX Runtime CPU 运行七段数字检测模型，分数阈值 0.25，类无关 NMS 0.45。
4. 保留 `0~9` 类，按中心横坐标排序并拼接；`dot/minus` 候选仅存入 JSON，不参与正数读数。最后两位固定为小数，原始字符串保留前导零。

模型来源：[adbartx/multimeter-ocr 的 digits.pt](https://github.com/adbartx/multimeter-ocr/blob/main/models/digits.pt)。

- 原权重：15,939,596 字节，Git blob SHA1 `555e491e5ba132cdc9f8d5f29acb1032b0cb82f0`，SHA256 `c841f72bfd65ef89150af1b3cc2546189fc856d2479206a403d9a7ef444206d6`。
- 导出模型：`models/digits.onnx`，10,573,343 字节，SHA256 `bfedd7ed24e43d741ef20717df5effde134aec9759a154b6ca334d5b1b4770e7`。
- 输入 `[1,3,640,640]`，输出 `[1,16,8400]`（坐标加 12 类：10 个数字、dot、minus），FP32，opset 12，不内置 NMS。
- 实际运行库 ONNX Runtime 1.31.0，CPUExecutionProvider，4 线程。预热后数字模型纯推理中位数约 **24.2 ms/窗口**，不包含窗口模型、JPEG 解码、预处理、后处理、绘图和文件写入，不代表手机性能。

## 验证和产物

- 已在首张、中间、末张窗口上比较数字模型的 PyTorch/ONNX 原始输出，以及自行实现的前后处理与 Ultralytics 官方预测框，全部通过。原始输出最大绝对差约 0.00193（包括坐标输出）。
- 验证中发现窄长窗口缩放时，整数尺寸取整后 X/Y 实际缩放率略有差异，已修正坐标还原并重新通过窗口模型原有对照检查。最终读取字符串未因此变化。
- `results/digits_export_verification.json`：数字模型数值/框坐标对照。
- `results/lcd_recognition/overview.jpg`：全部 30 张数字框及预测/人工参考。
- `results/lcd_recognition/annotated/`：逐张窗口数字框。
- `results/lcd_recognition/readings.json`：每位坐标、分数、原始数字串、固定两位小数读数及候选状态。
- `results/lcd_recognition/readings.csv`：便于核对的表格。

下一步优先处理不可读帧拒识和多帧一致性；微信小程序加载、真机速度及连续视频识别仍未测试。
